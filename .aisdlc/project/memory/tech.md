## 架构决策

### 1. 数据采集：Puppeteer + 指数退避重试

**决策**：使用 Puppeteer 而非简单 HTTP 爬虫

**原因**：
- 竞对网站通常采用 JS 动态渲染，HTTP GET 无法获取完整内容
- Puppeteer 支持浏览器自动化，能渲染 JS
- 7 天试用验证 > 95% 成功率（V-001）

**实装**：
- 重试次数：3 次（可配置）
- 退避时间：1s → 2s → 4s（指数增长）
- User-Agent 轮换（避免被识别）
- Timeout：30s（可配置）

**风险**：
- ⏳ 反爬机制升级可能导致采集失败（缓解：添加代理轮换、JS 延迟）

### 2. 变化检测：完全对比 vs 相似度

**决策**：完全对比（字段级，无相似度阈值）

**原因**：
- MVP 阶段追求准确性而非覆盖度
- 用户期望"确切变化"而非"类似变化"
- 30 字符内的 diff 也要报告（如价格变化）

**实装**：
- 算法：逐字段 strcmp（无算法开销）
- 精准度：100%（单元测试验证）
- 变化类型：pricing|content|structure|other（自动分类）

**风险**：
- ❌ 可能过度报告（如页面重新排版但内容不变）
- 缓解：V1.1 引入内容哈希过滤

### 3. 邮件投递：SendGrid 主通道 + Nodemailer 备选

**决策**：优先 SendGrid（SaaS），备选 Nodemailer（自建 SMTP）

**原因**：
- SendGrid：SaaS 99.99% 可用性，企业级，自动重试
- Nodemailer：内网 SMTP 兜底，不依赖第三方

**实装**：
- 重试：3 次（指数延迟）
- 批量投递：支持 BCC 多收件人
- 失败告警：记录日志 + 邮件日志表

**验证**：
- 30 次投递测试，> 99% 送达（V-002）
- 延迟 < 5 分钟（符合要求）

### 4. 定时任务：node-cron

**决策**：使用 node-cron 而非 Bull/RabbitMQ

**原因**：
- MVP 阶段任务量少（3 个定时任务）
- node-cron 无外部依赖，易运维
- 后期可升级到 Bull（Redis 支持）

**实装**：
- 采集：每天 02:00
- 检测：每天 02:30（采集后 30 分钟）
- 报告：每天 08:00（早晨发报）

**风险**：
- 单机执行（无分布式支持）
- 缓解：V2.0 改为消息队列

### 5. 数据库初始化：SQL Migration

**决策**：SQL migration 而非 ORM（如 Sequelize）

**原因**：
- MVP 表结构稳定，无需频繁变更
- SQL 手写便于优化与审查
- 支持复杂索引与约束定义

**实装**：
- 迁移文件：`db/migrations/001_init_schema.sql`
- 初始化工具：`scripts/init-db.js`
- Mock 降级：`src/db/mock-pool.js`（开发环境）

## 关键决策权衡

### 技术债

| 项 | 状态 | 影响 | 计划 |
|---|---|---|---|
| 无用户认证 | 已接受 | 竞对共享可见 | V1.1 补充权限隔离 |
