## 1. 结论摘要

- **一句话目标**：构建自动化竞品监控平台，让产品/运营团队通过定期邮件日报快速获取竞对动态情报，替代手工监控流程
- **本次 In / Out 的边界**：In - 竞对列表管理、多来源数据采集、变化检测、日报生成与邮件推送；Out - AI 自动生成分析、关键词/维度高级组合、第三方数据服务集成
- **推荐方案**：**竞对列表 + 爬虫采集 + 完全对比检测 + 模板化日报**（用户维护竞对名单，系统自动采集/对比/生成日报，通过邮件推送）
- **优先验证点**：V-001（爬虫数据采集可行性）、V-002（日报邮件投递可靠性）、V-003（变化检测准确度）

## 2. 推荐方案

**方案名**：竞对列表 + 爬虫采集 + 完全对比 + 模板日报

### 主流程 / 关键机制

1. **竞对列表管理**：用户在平台创建/编辑监控竞对名单（简单列表输入，无复杂维度组合）
2. **定时数据采集**：系统每天定时运行爬虫脚本，针对每个竞对抓取网站、社媒等来源数据（如定价、产品更新、社媒舆情等）
3. **增量变化检测**：将新采集的数据与前一天数据进行**完全一致比对**（字段级），发现差异则标记为"变化"
4. **日报生成**：对有变化的竞对，按模板自动生成日报条目（如"竞对X的价格从$100变成$120"）
5. **邮件推送**：每天固定时间（如早上8点）将日报发送给所有用户

### 关键边界/取舍

1. **MVP 不支持高级查询**：暂不支持关键词搜索、维度组合、自定义规则等，只支持竞对名单的简单增删改查
2. **内容生成采用模板化**：变化事实通过模板 + 变量替换生成，不使用 AI 自动生成（降低成本，加快交付）
3. **采集频率固定为日频**：暂不支持实时采集或其他频率（简化架构，便于初版交付）
4. **完全对比检测**：不使用相似度算法或关键字段筛选，任何字段变化都标记为"变化"（高精准，无漏报/误报的复杂性）

### 为什么选它

1. **快速交付**：所有设计决策都是"简化版"，最小化开发复杂度，能在 1-2 周内交付可用版本，快速验证用户价值
2. **高精准度**：完全对比检测方式简洁有效，避免算法复杂性；模板化日报内容准确可控
3. **可扩展性**：架构为后续升级预留空间（爬虫支持增加数据源、变化检测支持关键字段筛选、内容生成支持 AI 模式）

## 3. 备选方案

### 3.1 备选方案：第三方数据服务 + 人工分析

- **核心机制**：通过 API 接入 Crunchbase / Similarweb 等付费数据服务，获取竞对结构化数据；人工或半自动生成分析报告
- **主流程**：竞对列表 → 数据服务查询 → 数据同步 → 人工分析 → 报告生成 → 邮件推送
- **边界与取舍**：需要支付第三方服务费用；数据更新频率受第三方限制；人工分析成本高，不易扩展
- **适用前提**：对数据完整性/权威性要求极高；用户量小、可接受人工成本
- **不选原因**：(1) 成本高，MVP 阶段不适合；(2) 依赖第三方，可控性低；(3) 无法快速迭代

### 3.2 备选方案：AI 全自动分析

- **核心机制**：爬虫采集 → LLM 自动分析竞对数据，生成高价值洞察与建议 → 智能推送
- **主流程**：竞对列表 → 爬虫采集 → AI 分析 → 生成智能日报 → 邮件推送
- **边界与取舍**：AI 生成内容的准确度/幻觉需要严格控制；需要更多计算资源；内容生成策略需要精心设计
- **适用前提**：团队有 AI/NLP 技术积累；对内容质量容忍度高；预算充足
- **不选原因**：(1) 增加开发难度，延迟交付；(2) AI 幻觉风险，不适合 MVP；(3) 成本和技术风险都高

### 3.3 备选方案：完全手工输入 + Web 平台查看

- **核心机制**：用户手工上传竞对信息或手动输入监控数据；系统提供 Web 界面查看历史对比
- **主流程**：竞对数据手工输入 → 数据版本管理 → Web 平台查询对比 → 按需导出
- **边界与取舍**：完全依赖用户手工输入，无自动化；交付是 Web 平台而非邮件推送；用户体验差
- **适用前提**：无技术能力做爬虫；数据量小；用户主动性强
- **不选原因**：(1) 与原需求的"自动化"核心价值不符；(2) 用户体验差，难以推广

## 5. 验证清单

### V-001：爬虫数据采集可行性验证

- **风险/假设**：爬虫采集多源数据（网站、社媒）的稳定性和准确度是否可行；是否会遇到反爬或数据格式变化的问题
- **方法**：选取 3-5 个典型竞对目标，实现爬虫脚本采集其网站/社媒数据，运行 7 天以上，统计采集成功率、数据质量、反爬情况
- **成功/失败信号**：采集成功率 > 95%、有效数据字段 > 80% 为成立；否则不成立
- **Owner**：后端/爬虫工程师
- **截止**：需求评审后 5 天
- **触发动作**：成立 - 继续实现；不成立 - 评估第三方数据服务或调整采集策略

### V-002：日报邮件投递可靠性

- **风险/假设**：邮件日报的投递率、送达速度、用户可达性是否满足业务要求
- **方法**：搭建邮件投递模块，进行 30 次测试邮件投递；统计送达率、投递延迟、邮件落垃圾箱比率
- **成功/失败信号**：送达率 > 99%、投递延迟 < 5 分钟、垃圾箱比率 < 1% 为成立；否则不成立
- **Owner**：后端/运维
- **截止**：需求评审后 7 天
- **触发动作**：成立 - 上线；不成立 - 优化邮件模板或更换邮件服务商

### V-003：变化检测准确度验证

- **风险/假设**：完全一致比对方式是否会导致大量虚假正例（误报）或遗漏真实变化；用户能否接受变化粒度
- **方法**：选取 5 个竞对，运行 14 天变化检测，人工抽样审查 50+ 条检测结果，计算精准度、误报率
- **成功/失败信号**：精准度 > 95%、误报率 < 5% 为成立；否则不成立
- **Owner**：产品/QA
- **截止**：需求评审后 10 天
- **触发动作**：成立 - 上线；不成立 - 增加关键字段筛选或相似度阈值

### V-004：用户可用性验证

- **风险/假设**：产品/运营团队对日报内容质量、更新频率、UI 易用性的满意度；是否满足实际决策需求
- **方法**：邀请 3-5 个典型产品/运营团队成员试用 7 天，收集反馈（NPS / 内容质量评分 / 易用性评分）
- **成功/失败信号**：NPS >= 50、内容满意度 >= 4/5、易用性 >= 4/5 为成立；否则不成立
- **Owner**：产品
- **截止**：MVP 交付后 7 天
- **触发动作**：成立 - 扩大用户群；不成立 - 迭代内容模板或 UI 设计

### V-005：数据采集成本评估

- **风险/假设**：爬虫采集的服务器成本、网络带宽、存储成本是否可控；随着竞对数量增加是否线性增长
- **方法**：统计 7 天内 10 个竞对的采集成本（API 调用数、数据传输、存储占用），建立成本模型
- **成功/失败信号**：单竞对日均成本 < $0.1 为成立；否则需要优化采集策略
- **Owner**：运维/成本分析
- **截止**：需求评审后 7 天
- **触发动作**：成立 - 按计划扩展；不成立 - 优化采集频率或增量策略

## 8. Mini-PRD（简化版交付范围）

### MVP 范围

**In**：
- 用户可添加/编辑/删除监控竞对列表
- 系统每天自动采集竞对数据（网站、社媒等基本来源）
- 系统识别并标记数据变化（完全一致比对）
- 系统生成日报（模板化内容，包含变化的竞对及简要描述）
- 系统每天固定时间（如早 8 点）发送日报邮件给订阅用户
- 用户可查看历史日报（可选：Web 界面查询）

**Out**：
- AI 自动生成分析和建议（后续迭代）
- 关键词搜索、维度组合、自定义规则（后续迭代）
- 实时采集和推送（后续迭代）
- 第三方数据服务集成（后续迭代）
- 复杂权限模型（初版仅支持简单订阅）

### 验收标准（AC）

1. 用户能通过简单列表新增竞对名单，支持 CRUD 操作
2. 采集模块每天定时运行，针对所有在线竞对抓取数据，采集成功率 > 95%
3. 变化检测模块正确识别数据变化，精准度 > 95%
4. 日报生成模块自动生成日报条目（仅包含有变化的竞对），无手工编辑
5. 邮件投递每天定时发送，送达率 > 99%，投递延迟 < 5 分钟
6. 用户收到日报邮件后能点击链接查看完整报告（可选：Web 界面）
7. 系统支持至少 10 个并发竞对监控，无性能下降

### 交互变化结论

**无新增交互复杂性**。MVP 版本交互简洁：
- 竞对列表管理：简单的 CRUD 表单
- 日报查看：邮件 + 可选 Web 界面，无复杂导航或状态转移
- 建议后续原型阶段补充"竞对列表管理"UI 和"日报查看"页面原型，确保易用性

### 影响面

- **新增页面**：竞对列表管理页面、日报详情页面（Web）
- **新增后端接口**：`POST /competitors`、`GET /competitors`、`PUT /competitors/{id}`、`DELETE /competitors/{id}`、`GET /reports/{date}`
- **新增数据表**：`competitors`（竞对信息）、`data_snapshots`（采集数据快照）、`changes`（检测变化记录）、`reports`（日报记录）
- **新增定时任务**：`CronJob: collect_competitor_data`（采集）、`CronJob: detect_changes`（变化检测）、`CronJob: generate_and_send_reports`（日报生成与邮件投递）
- **依赖现有模块**：用户认证（读）、邮件系统（写）
- **权限点**：竞对列表读写权限、日报查看权限
